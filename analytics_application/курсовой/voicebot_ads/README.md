## 🗄️ База данных (PostgreSQL)

Схема базы данных включает 6 таблиц:
1. `Statuses` — справочник статусов аварийных заявок («Принят», «В работе», «Выполнен», «Отменён», «Дублирующий»);
2. `IncidentTypes` — классификатор инцидентов и уровней срочности (1 — критический, 2 — высокий, 3 — стандартный);
3. `Operators` — справочник дежурных диспетчеров и рабочих смен («День», «Ночь», «Сутки»);
4. `Incidents` — реестр аварийных ситуаций с адресами, описанием и временными метками;
5. `Calls` — центральный журнал входящих телефонных вызовов с признаком `bot_handled` (обработка роботом);
6. `CallLogs` — пошаговая стенограмма диалога бота с заявителем (вопросы бота, распознанные ответы жителя).

В схеме реализованы 4 аналитических представления (VIEW):
- `v_calls_by_type` — статистика обращений по категориям аварий и доля автоматизации;
- `v_incidents_with_status` — реестр инцидентов с расчетом времени устранения в часах;
- `v_avg_bot_handling` — сравнительный анализ хронометража звонков: робот vs дежурный оператор;
- `v_dashboard` — сводные агрегированные показатели операционной деятельности службы.

## 🚀 Инструкция по запуску

### 1. Подготовка базы данных
Создайте базу данных в PostgreSQL и примените скрипт `schema.sql`:

```bash
# Создание базы данных
createdb -U postgres voicebot_ads

# Накатывание схемы, представлений и тестовых данных
psql -v ON_ERROR_STOP=1 -U postgres -d voicebot_ads -f schema.sql

# Выполнение дополнительных аналитических запросов из раздела 2.2
psql -v ON_ERROR_STOP=1 -U postgres -d voicebot_ads -f queries.sql
```

> **Примечание:** При необходимости укажите ваши параметры подключения в `main.py` в словаре `DB_CONFIG`:
> ```python
> DB_CONFIG = {
>     "host": "localhost",
>     "port": 5432,
>     "database": "voicebot_ads",
>     "user": "postgres",
>     "password": "your_password"
> }
> ```

### 2. Установка зависимостей Python
Рекомендуется использовать виртуальное окружение:

```bash
python3 -m venv venv
source venv/bin/activate  # На Linux/macOS
# venv\Scripts\activate   # На Windows

pip install -r requirements.txt
```

### 3. Запуск веб-сервера FastAPI

```bash
python3 main.py
```
или через uvicorn:
```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 4. Доступ к интерфейсу и API
- **Интерактивный веб-дашборд:** [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- **Автоматическая документация Swagger API:** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## 📊 Доступные REST API маршруты

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/` | Главная страница аналитического дашборда |
| `GET` | `/api/dashboard` | Сводные KPI метрики (звонки, инциденты, доля автоматизации) |
| `GET` | `/api/calls-by-type` | Распределение звонков по типам инцидентов и среднее время |
| `GET` | `/api/avg-handling` | Сравнение скорости обработки звонков ботом и диспетчером |
| `GET` | `/api/incidents` | Реестр инцидентов (поддерживает query-параметр `?status=...`) |
| `GET` | `/api/calls` | Журнал всех телефонных соединений |
| `GET` | `/api/calls/{call_id}/log` | Пошаговая стенограмма диалога бота для звонка `call_id` |
| `GET` | `/api/operators` | Список операторов и их текущий статус активности |
| `GET` | `/api/operators/stats` | Аналитика результативности и средней скорости закрытия заявок операторами |
