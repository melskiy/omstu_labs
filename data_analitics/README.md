# 🎵 Music Tracks Analytics: DWH & Analytical Dashboard

Комплексный проект, реализующий требования **4 лабораторных работ** по двум дисциплинам:
1. **«Администрирование больших данных» (АБД)** — Лабораторные работы №1 и №2
2. **«Высокопроизводительная обработка и анализ данных» (ВОиАД)** — Лабораторные работы №1 и №2

---

## 🏛️ Архитектура решения

Хранилище данных построено по многослойной архитектуре в **PostgreSQL 16**:
1. **`SOURCE` (`source.music_tracks`)**: Исходный датасет `music_project.csv`, сохраненный в максимально близком виде + синтетически сгенерированный атрибут `dt (DATE)`, строго согласованный с днем недели `Day`.
2. **`STAGING` (`staging.music_tracks`)**: Промежуточный буфер, данные переносятся *as is* (без изменений) PL/pgSQL функцией `public.load_source_to_staging()`.
3. **`ODS` (`ods.music_tracks`)**: Слой очищенных данных. Инкрементальная загрузка за период `[p_sdt, p_edt]` через PL/pgSQL функцию `public.load_staging_to_ods(p_sdt, p_edt)`. Идемпотентность, удаление сетевых дубликатов, нормализация категорий (хип-хоп, электроника), обработка пропусков (`unknown`). Фиксация аудита в таблице `ods.data_quality_log`.
4. **`DDS` («Снежинка»)**: Нормализованное хранилище:
   - Измерения: `dds.dim_artists`, `dds.dim_genres`, `dds.dim_tracks` (ссылается на артистов и жанры), `dds.dim_users`, `dds.dim_cities`, `dds.dim_time`.
   - Факты: `dds.fact_listens`.
   - Загрузка функцией `public.load_ods_to_dds(p_sdt, p_edt)`.
5. **`MART` (`mart.city_genre_popularity`)**: Аналитическая витрина популярности жанров по городам и периодам в PostgreSQL.
6. **`ClickHouse` (`music_analytics.city_genre_popularity`)**: Целевая аналитическая витрина во второй СУБД (OLAP) на движке `ReplacingMergeTree`.

## 🚀 Быстрый старт и запуск

### 1. Запуск через Docker Compose (Рекомендуемый способ)
В корне директории `data_analitics` выполните:
```bash
docker compose up -d --build
```

Сервисы и веб-интерфейсы доступны по адресам:
- 🌐 **Интерактивный дэшборд Streamlit**: [http://localhost:8501](http://localhost:8501)
  * Страница **`3_db_viewer`**: встроенный веб-инспектор таблиц всех слоев PostgreSQL (`SOURCE`, `STAGING`, `ODS`, `DDS`, `MART`) и ClickHouse, с DDL-схемой, выгрузкой в CSV и SQL-консолью.
- ⚡ **Официальный ClickHouse Web Client (Play)**: [http://localhost:8123/play](http://localhost:8123/play)
  * Логин: `default`, пароль: `ch_password`, база: `music_analytics`.
- 🐘 **Параметры прямого подключения к PostgreSQL** (через DBeaver, DataGrip, pgAdmin):
  * Хост: `localhost`, Порт: `5432`, База: `music_dwh`, Пользователь: `dwh_user`, Пароль: `dwh_password`.
- ⚡ **Параметры прямого подключения к ClickHouse**:
  * Хост: `localhost`, HTTP порт: `8123`, Native порт: `9000`, База: `music_analytics`, Пользователь: `default`, Пароль: `ch_password`.

## 🕹️ Пошаговое выполнение лабораторных работ

Вы можете выполнить все шаги прямо из графического интерфейса Streamlit на главной странице ([http://localhost:8501](http://localhost:8501)), нажимая кнопки в секции **«Панель управления ETL-пайплайном»**, либо через консоль:

### Шаг 1. Инициализация схем PostgreSQL (АБД Лаб. 1)
```bash
python3 app/etl.py
```
*(Применяет `01_init_schema.sql`, `02_dds_schema.sql`, `03_functions.sql`, `04_mart.sql`)*

### Шаг 2. Загрузка исходного датасета в SOURCE (АБД Лаб. 1)
```bash
python3 app/loader.py
```
*Загружает ~65 000 строк в `source.music_tracks`, генерируя поле `dt (DATE)`, соответствующее дню недели `Day`.*

### Шаг 3. Запуск инкрементального пайплайна (АБД Лаб. 1)
```python
# Перенос в STAGING (as is)
# Очистка и инкрементальная загрузка в ODS:
# public.load_staging_to_ods('2024-01-01', '2024-06-30')
# Загрузка фактов и измерений DDS:
# public.load_ods_to_dds('2024-01-01', '2024-06-30')
# Обновление аналитической витрины:
# public.refresh_mart('2024-01-01', '2024-06-30')
```

### Шаг 4. Генерация синтетических партий (АБД Лаб. 2)
```bash
python3 app/generator.py
```
*Генерирует и загружает 2 последовательные партии (`synthetic_batch_1`, `synthetic_batch_2`) с дефектами для проверки очистки.*

### Шаг 5. Перенос витрины в ClickHouse и контроль согласованности (АБД Лаб. 2)
```bash
python3 app/clickhouse_transfer.py
```
*Переносит витрину `mart.city_genre_popularity` в таблицу ClickHouse с движком `ReplacingMergeTree` и выводит таблицу сверки метрик.*

## 📊 Страницы дэшборда Streamlit

### Страница 1: `1_eda` (ВОиАД Лабораторная работа №1)
- Общие показатели источника (объем, столбцы, размер).
- Сводная таблица заполненности и график пропусков (в `artist`, `Track`, `genre`).
- Анализ распределений: по часам суток (00-23), дням недели, популярности жанров и артистов.
- Сравнение вкусов пользователей Москвы и Санкт-Петербурга.
- Выявление неявных дубликатов (`hip` vs `hiphop`) и сетевых дублей.
- **Раздел «Предлагаемый алгоритм очистки данных»** с формализованной таблицей критериев и способов обработки.

### Страница 2: `2_comparison` (ВОиАД Лабораторная работа №2)
- Воронка трансформации объемов данных по слоям `SOURCE` $\rightarrow$ `STAGING` $\rightarrow$ `ODS` $\rightarrow$ `DDS` $\rightarrow$ `MART`.
- **Аудит качества по фактическому журналу `ods.data_quality_log`** (число устраненных дублей, исправленных пропусков).
- Сопоставление характеристик исходного набора и синтетических данных.
- Таймлайн объемов по синтетическому полю `dt`.
- **Раздел «Проверка согласованности аналитических витрин»**: детальное сопоставление метрик PostgreSQL и ClickHouse с подтверждением 100% совпадения показателей.
